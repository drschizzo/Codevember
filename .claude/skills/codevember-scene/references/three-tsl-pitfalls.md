# Pièges three.js 0.186 WebGPU / TSL

Relevés en construisant Hollow, Membrane, Orrery et Tesseract, avec leurs remèdes. Lis-les avant d'écrire du TSL ; quand un objet disparaît, qu'une surface est noire ou que la page gèle, cherche ici d'abord.

**Les trois réflexes**
- Un objet invisible (seule son ombre reste) = pipeline invalide : regarde la console (`errors` en `?debug`, crochet posé AVANT la compilation), compte les varyings (≤ 15 en double face) et les tampons de sommets (≤ 8).
- Une surface noire = NaN (normale nulle, `pow(0, x)`, vitesse infinie × 0) ou attribut manquant (`normal`), rarement la lumière.
- Plusieurs rendus dans le même tour (export, images fixes, préchauffage) = `renderer._nodes.nodeFrame.update()` avant chacun.

(Notes d’origine, en anglais.)


- `PI` exported by `three/tsl` is a node: `x.mul(PI * 2)` produces `NaN` in WGSL. Use `Math.PI` for JS arithmetic.
- `transformNormalToView(v)` normalizes; a zero vector → NaN normal → black surface. Use `modelViewMatrix.mul(vec4(v, 0)).xyz` instead.
- `chromaticAberration(node, s, null)` → "Cannot read properties of null (reading 'build')": pass `vec2(0.5, 0.5)` explicitly.
- GTAO `ao(depth, normal, camera)` needs a texture node for normals: put `normalView` directly in the MRT (half-float targets), not `unpackRGBToNormal(...)`.
- `godrays(depth, camera, light)` reads `light.shadow.map` at build time: build it only after the first shadow render.
- `MotionBlur.js` needs a texture input (and over-brightens: n+1 samples / n); `TRAANode.getTextureNode()` is null before setup. Hollow uses its own shutter blur on the scene pass texture.
- `bumpMap()` does nothing on procedural (non-UV) heights: use a derivative-based perturbation (Mikkelsen) instead.
- MaterialX noises (`mx_noise_float`, `mx_worley_*`, `mx_fractal_*`) are extremely expensive per pixel (Hollow went 50 ms → 0.7 ms by sampling a precomputed periodic 3D noise volume and branching per surface with `struct` + `If`).
- `PCFSoftShadowMap` is removed in WebGPU (falls back to PCF). Shadow casters can be selected with `light.shadow.camera.layers.mask` (any bit other than 0 = used as-is).
- `select(cond, a, b)` compiles to an if/else: a shared `.once().toVar()` node (e.g. `normalViewGeometry`) first referenced inside it is assigned in one branch only → wrong lighting everywhere (looked like lost shadows). In `normalNode`, use a branchless `mix(a, b, step(...))` and keep both sides NaN-free (NaN also leaks through screen derivatives).
- Inside `normalNode`, don't reference `normalView` (it is the material normal itself); use `normalViewGeometry`.
- Profile with the animation loop paused and `await device.queue.onSubmittedWorkDone()`; numbers right after a config change include async pipeline compilation.
- Sharing one node material between regular Meshes and an InstancedMesh breaks velocity (whole-frame motion-blur smear): give the instanced mesh its own material instance (Hollow 2026-11-08).
- Thin instanced cones (spines) receiving shadows self-shadow to black: `receiveShadow = false`, keep `castShadow`.
- Colored shadows: `renderer.shadowMap.transmitted = true` + `material.castShadowNode = vec4(color, 1)` works for point-light cube shadows too; opaque casters with a colorNode/mask write black. TSL method chaining `a.mix(b, t)` means `mix(b, t, a)`.
- Vertex deformation via `material.positionNode` (Fn that also assigns `normalLocal`, `tangentLocal`, `positionPrevious`, and `varyingProperty` varyings) works; shadow pass reuses `positionNode` of the shadow material. `positionGeometry` = rest position for patterns.
- The Claude browser pane throttles rAF to ~1–4 fps at times: verify by calling the render function manually + `device.queue.onSubmittedWorkDone()` (Hollow has `hollow.shot(ph)` / `hollow.view(layer, x)` in `?debug`).
- (Earlier note blamed `uniform().onObjectUpdate(...)` for per-object values going wrong; per-object uniform buffers were verified sound on 2026-11-08 — the real culprit was most likely the shadow render-object cache below. Hollow still derives depth in the shader: x = log(modelScale.x / D) / log(ratio).)
- Shadow pass caches the render object under (mesh, light's shared shadow override material): node properties don't enter the cache key, so changing `mesh.material` (e.g. to one with a `positionNode`/`maskShadowNode`) is NOT picked up — the pipeline built from the first source material stays until that material is `dispose()`d. Never switch a shadow caster away from a shared, never-disposed material; give each owner its own material and dispose the old one (Hollow 2026-11-08: iris frozen in the shadow map after changing scene → light spots, desynced iris).
- Swapping `mesh.geometry` does NOT recompile: the render object (mesh, material) keeps the shader built from the attributes of the geometry it had when first drawn (`setGeometry` only swaps buffers; the attribute list in the cache key is re-checked only when `material.version` changes). A material applied before its async geometry arrives, and rendered meanwhile, ends up compiled without e.g. `rigA` → `attribute()` reads 0 forever for those objects. Hollow 2026-11-08: iris frozen closed on the copies drawn during loading → wrong at scene start and every C loops. Fix: rebuild (and dispose the old) materials whenever geometry is swapped (dispose also invalidates shadow-pass render objects).
- Debug readback of render targets: rows are padded to 256 bytes (stride = ceil(W*bytesPerPixel/256)*256); index with that stride or results are garbage.
- FRAME-type nodes (PassNode scene pass, shadow maps once per camera/frame, VelocityNode camera matrices) only refresh when `nodeFrame.frameId` advances, which only happens in `setAnimationLoop`. Several renders in one tick (video export, debug shots) reuse the first image: call `renderer._nodes.nodeFrame.update()` before each out-of-loop render.
- Debug readback: `drawImage`/`createImageBitmap` of the WebGPU canvas came back stale in the Claude pane; read `post.nodes.scenePass.renderTarget` (or TRAA's `_resolveRenderTarget`) with `renderer.readRenderTargetPixelsAsync` instead. Rendering the scene into a plain RenderTarget fails for materials with an `mrtNode` (empty WGSL output struct).
- Never zero a velocity by multiplying (`velocity.mul(flag)`): an infinite velocity (object that jumped / previous position behind camera) × 0 = NaN, which poisons the TRAA history (whole screen goes flat for a while). Use `select(length(v.xy).lessThan(k), v, vec4(0))` and guard the color fed to `traa()`.
- Rigged (vertex-animated) pieces need a real `positionPrevious` (pose at the previous frame's parameters, via global "previous" uniforms), not the current pose: zero self-velocity makes TRAA keep stale images of moving parts.
- WebGPU allows only 8 vertex buffers per pipeline (`maxVertexBuffers` 8): position+normal+tangent+surf+pat+3 rig attributes is the max; a 9th attribute fails pipeline creation silently-ish (console error, object invisible). Pack attributes (Membrane 2026-11-08).
- Built-in `transmission` samples ONE shared framebuffer copy per render, so nested transmissive shells can't see each other. Instead give each material its own `viewportMipTexture()` (copied once per render, at the first draw that uses it, keyed by its texture) and order draws with `renderOrder` (back faces outer→inner, then front faces inner→outer); add the backdrop as emissive on an opaque material (Membrane).
- `MeshSSSNodeMaterial` (thicknessColorNode etc.) adds a Barré-Brisebois translucency term per light; a point light at the centre of nested shells makes every shell glow (milky veil) — keep it weak, put silhouettes on a shadowed back spotlight.
- Raw WebGPU compute alongside three (Membrane 2026-11-08): use `renderer.backend.device`; to let three render from buffers your WGSL writes, make a `THREE.StorageBufferAttribute`, call `renderer.backend.createStorageAttribute(attr)` then `renderer.backend.get(attr).buffer` (usage STORAGE|VERTEX|COPY) and read it in TSL with `storage(attr,'vec4',n).toReadOnly().element(i)`; never bump `attr.version` (three would re-upload over your data). Submit your compute before `post.render()` (same queue = ordered).
- WGSL traps: `meta` and `target` are reserved words (shader module fails, every pipeline invalid). Integer indices stored as bit patterns in an `array<f32>` are denormals and can be flushed to 0 — store them as plain float values. Vertex-centric Jacobi must AVERAGE corrections per particle (incl. zero-length bonds at junctions) or it diverges at small time steps; `pow(0, x)` can yield NaN on GPU — clamp the base.
- Debug compile errors with `device.createShaderModule({code}).getCompilationInfo()`; console only shows the cascade of "Invalid ComputePipeline".

- A vertex-deformed mesh whose `positionNode` assigns `normalLocal` still needs a `normal` geometry attribute: without it, lighting is wrong (back faces render dark, front faces washed out) with no error (Membrane 2026-11-08). WGSL also reserves `smooth` (like `meta`, `target`).
- Expensive per-pixel work behind `If(...)` (TSL, inside a `Fn`): compute screen derivatives (`dFdx`, `fwidth`) OUTSIDE the branch and pass an analytic gradient in (Mikkelsen with given dh/dx, dh/dy). `If` only works inside a `Fn` stack (Membrane wrinkles 2026-11-08: 3.2 ms → 0.6 ms with a slope threshold).
- Hardware-blended draws in an MRT pass: the same blend state applies to every attachment, with each attachment's OWN src alpha. Output vec4(v, 1) to replace an attachment, vec4(0) to keep dst. Blending needs `material.transparent = true`, which moves the draw to the transparent list: make all mutually ordered draws transparent (NoBlending for the opaque ones) so `renderOrder` still orders them. Fog applies before blending: scale the transmitted dst by (1 − fog) to match a copy-based path.
- Per-layer `viewportMipTexture` copies cost ~0.6 ms each at 1.9 Mpx (copy + mip chain), whatever the object's screen size. GTAO under TRAA: `samples` 8 instead of 16 saves ~1 ms.
- Selective lighting (Tesseract 2026-11-08): `material.lightsNode = lights([...])` works (light nodes are shared per light, shadows included). Every material NOT given a list (e.g. the floor) still evaluates ALL scene lights: adding 8 lights for linked materials made the full-screen floor cost +11 ms until it got its own list. Fragment-bound scenes: lights per pixel dominate, vertex work (even 7 projections/vertex) did not show in frame time.
- AO into indirect only: prePass `pass()` with `transparent = false` + `mrt({ output: normalView })`, GTAO on it, `scenePass.contextNode = builtinAOContext(ao)` (three 0.186). Costs ~1–1.5 ms of extra vertex work.
- `renderer.compileAsync` / `PassNode.compileAsync` did not remove the multi-second freeze on scene load (likely TSL→WGSL generation on the main thread); PassNode.compileAsync also ignores the pass `contextNode`, so its pipelines don't match the real render.
- Every render object's dynamic cache key includes the SCENE LightsNode key, built from scene lights in traversal order (unsorted): re-parenting groups that contain lights (Planétaire v2 nested worlds) reorders them → every material recompiles → multi-second freeze. Keep lights in fixed top-level rigs (matrixAutoUpdate=false, copy the owner's matrixWorld each frame) (2026-11-09).
- Shader compile freezes (seconds) can't be moved off the main thread; a loading animation drawn in a worker on an OffscreenCanvas (`transferControlToOffscreen`, worker rAF) keeps running at full rate through them (Planétaire v2 2026-11-09, ~110 fps measured during a 6 s compile).
- PassNode scene pass is skipped when nodeFrame.frameId didn't advance: a "precompile" render during loading must call `renderer._nodes.nodeFrame.update()` first or it compiles nothing.
- `fwidth`-based dithered `maskNode` (IGN + `frameId`) gives AA'd discard edges under TRAA; use a plain 0.5 threshold for `maskShadowNode`.
- Sync `createRenderPipeline` (three's default at first draw) blocks Chrome's GPU process during each shader compile → the whole page display freezes, even a loader drawn in a worker on an OffscreenCanvas (worker rAF keeps ticking, so frame counts don't show it; probe with a WebGL `readPixels` round trip from the worker). Fix (Planétaire v2 2026-11-09): wrap `renderer.backend.createRenderPipeline(ro, promises)` to pass a promise list (→ `createRenderPipelineAsync`) and set `backend.get(ro.pipeline).error = true` until resolved (three's draw skips errored pipelines), re-render until no new pipeline; reveal objects in small batches; then `envTexture.needsPMREMUpdate = true` (PMREM was generated with skipped draws). Stalls 1.4 s → 0.1 s.
- three compiles one shader per `InstancedMesh` (material cache key includes `object.uuid`, instance uniform buffer named `NodeBuffer_<id>`): hundreds of shaders, seconds of load. Use a plain Mesh + `InstancedBufferGeometry` with the instance matrix in `InstancedInterleavedBuffer` attributes (im0..3, ip0..3 for the previous frame) applied in `material.positionNode` (assign `normalLocal`, `positionPrevious`): one shader per material (477 → 181 shaders).
- WebGPU allows 16 fragment inputs INCLUDING `front_facing` (DoubleSide) → 15 varyings. Over it: "Total fragment input variables count (17) exceeds the maximum (16)", three flags the pipeline and silently skips the draw — the object vanishes from scene pass and prepass, only its shadow remains (Tesseract 2026-11-10: every anisotropic panel was missing on desktop). Costs to know: a `varyingProperty` assigned in the vertex stage is interpolated even if no fragment reads it; `velocity` in an MRT makes `positionLocal` AND `positionPrevious` varyings (so read `positionLocal` in the fragment instead of a custom "projected position" varying); each attribute read in the fragment is one varying; anisotropy adds the tangent. Pack scalars into vec3/vec4. Count with `renderObject.getNodeBuilderState().fragmentShader` (hook `backend.draw`, check `backend.get(ro.pipeline).error`).
- Warm-up renders must disable `frustumCulled` (off-screen objects are not compiled) and cover hidden-by-`visible` states.
- Dynamic room probe without PMREM (Tesseract 2026-11-10): materials with an `mrtNode` can't be rendered by `renderer.render()` into a plain/cube target, so the probe draws twin meshes (shared geometry, `MeshLambertNodeMaterial`, same `positionNode`/`maskNode`, explicit `lightsNode`) on layer 1 with `CubeCamera` children `layers.set(1)`; one face per frame via `renderer.setRenderTarget(cubeRT, face); renderer.render(scene, cubeCam.children[face])` (set `coordinateSystem` + `updateCoordinateSystem()` first), `generateMipmaps` on. Sample with `cubeTexture(rt.texture, cameraWorldMatrix.mul(vec4(dirView,0)).xyz).level(l)`: lowest mips along the normal = diffuse bounce, roughness-scaled mip along the reflection = specular; add to `emissiveNode`. Cost ≈ 0.3 ms.
- Accumulation export: render the post chain into an RGBA8 target N times with jitter (time, lens offset + `lookAt` focus point, `camera.setViewOffset` sub-pixel, light position), add into an RGBA16F target with a `QuadMesh` (`AdditiveBlending`, `sRGBTransferEOTF` decode, weight 1/N; rgba32float is not blendable), present with `toneMapped: false`. Turn TRAA and post motion blur off for those renders.

**Ajouts (Calcin, 2026-11-10)**
- `DoubleSide` ne dispense pas d'orienter les triangles : une face vue de dos voit sa normale retournée, donc un sol dont les triangles sont tournés vers le bas n'est plus éclairé du tout (noir sous la lampe), alors que son émission, elle, s'affiche. Oriente les faces vers le spectateur ou d'après les normales des sommets (comme `Buffers.tri`).
- Une transmission physique devant un fond noir ne montre que du noir : la teinte d'un verre ne se lit que devant du clair (voir rendering.md, « fond clair »).
- Tout un nuage d'objets (des centaines d'éclats, des dizaines de milliers de grains) tient en un maillage chacun, si leur mouvement est une fonction analytique du temps calculée dans `positionNode` à partir d'attributs par sommet ou par instance (`InstancedInterleavedBuffer`) : 7 tampons de sommets (position, normal, surf, 4 vec4) restent sous la limite de 8, et la pose à l'image précédente donne les vecteurs vitesse.
- Les fonctions importées de `three/tsl` (`smoothstep`, `mix`, `floor`, `clamp`, `min`…) sont des nœuds : appelées dans du code JS (animation sur le CPU), elles renvoient un objet et tout calcul qui suit devient `NaN` (Calcin : les appareils avaient une position verticale `NaN` et ne s'affichaient pas, sans erreur). Donne aux aides JS d'autres noms (`sstep`), et n'importe pas de TSL dans les modules de calcul pur.
- Un nom TSL importé peut être masqué par une variable locale (`const floor = new Mesh()` puis `floor(q)` dans un shader : « floor is not a function ») : renomme l'import (`floor as tFloor`).
- Une caméra qui passe sous un sol relevé (cuvette, gorge du cyclorama) voit l'envers du décor et rend une image noire, sans erreur. Contraindre la hauteur de la caméra au-dessus de la fonction du sol, et tester les cadrages extrêmes de chaque humeur.
- Une variable (`varyingProperty`) affectée dans le `positionNode` n'est pas fiable dans la passe d'ombre : un `maskShadowNode` qui la lit peut retirer l'objet de la carte d'ombre (Calcin : le verre ne portait aucune ombre). Recalcule ce masque depuis les attributs et les uniformes.
- Une fonction et une variable locale de même nom (`const plateAngle = …` puis `let plateAngle`) : l'erreur n'apparaît qu'à l'exécution, dans `warm()` ; l'écran de chargement l'affiche, lis-le.
- **Un matériau à transmission (`transmissionNode`, `transmission > 0`) ne porte aucune ombre** dans three.js 0.186 WebGPU, quels que soient `castShadowNode`, `maskShadowNode` et `shadowMap.transmitted` (vérifié : le même matériau sans transmission porte son ombre). Remède : un double invisible du maillage (même géométrie, même `positionNode`, `MeshBasicNodeMaterial` avec `castShadowNode` teinté), rangé dans un calque que seule la caméra d'ombre voit (`mesh.layers.set(2)`, `light.shadow.camera.layers.enable(2)`), enfant du maillage visible pour en suivre la transformation.

**Ajout (Fold, 2026-11-11)**
- Pipelines asynchrones du chargement : la promesse de `createRenderPipeline(ro, promises)` peut se résoudre avant que three.js n'ait rangé `pipelineData.pipeline`. Un crochet qui ne lève `data.error` que si `data.pipeline` existe déjà laisse alors l'objet marqué en erreur pour toujours : il n'est jamais dessiné (Fold : le paillage, puis le pot, absents de la première scène après un rechargement, sans message). Garder les pipelines marquées dans un ensemble et les revérifier après la compilation (`flushPipes` de `fold/src/main.js`), et signaler en erreur celles qui restent bloquées.
- Une nappe à une seule face (`FrontSide`) ne porte pas d'ombre visible quand la face éclairée est l'autre : un pétiole ailé plat n'avait pas d'ombre. Construire les limbes en lames fermées.
- (Géométrie, pas three.js, mais même famille d'erreur silencieuse) Une distance à un profil non signée fait passer « dedans » pour « dehors » : une dichotomie de contact peut converger de l'autre côté de la paroi. Signer la distance (négative dans la matière).
- Caméra : un garde-fou appliqué image par image par paliers (« recule de 3 % tant qu'elle est dans la cloche ») fait sauter la caméra d'avant en arrière au bord de l'obstacle (Fold, c2p3j5 : 990 u/s² à 120 i/s). Calculer, sur la trajectoire échantillonnée, la distance minimale exacte (dichotomie, définie partout : une fonction continue), l'appliquer comme plancher par un maximum adouci, interpoler en Catmull-Rom ; tester l'accélération image par image.
- Motif procédural fin (cercles de tournage, cernes) : l'effacer avant la fréquence du pixel (Nyquist : 0,5 cycle par pixel ; viser 0,1–0,3) sinon il se replie en larges bandes (moiré) ; une onde en dents de scie (fract) dessine des marches : préférer une onde triangulaire.

**Ajouts (Moss, 2026-11-10)**
- `SpotLight.colorNode` (texture projetée procédurale) doit être une fonction TSL `Fn(([uv]) => …)` qui renvoie un `vec3` ; une fonction JS ordinaire échoue à la construction (« getCacheKey is not a function »).
- Les textures `FloatType` ne sont pas filtrables par défaut en WebGPU : pour une carte échantillonnée en linéaire (relief, champ), utilise `HalfFloatType` (conversion float → demi-flottant écrite à la main dans un worker, `THREE.DataUtils` n'y est pas) ; dans un vertex shader, lis-la avec `.level(0)`.
- Une erreur levée dans le `.then(ok)` d'une requête au worker n'est pas rattrapée par le second argument de `.then(ok, err)` : le chargement attend alors pour toujours, sans message. Termine la chaîne par `.catch(…)` qui affiche l'erreur sur l'écran de chargement.
- (JS, même famille d'erreur silencieuse) Une fonction locale qui porte le nom d'un utilitaire importé (`const add = (mesh) => …` masquant l'addition de vecteurs `add`) casse tout code de la même portée qui comptait sur l'import, souvent seulement pour certaines humeurs. Renomme l'import (`add as vadd`) — et ne remplace jamais un nom par expression régulière sans exclure les appels de méthode (`.add(` des nœuds TSL).
- Un tableau d'uniformes (`uniformArray(vec4[], 'vec4')`, mis à jour à chaque rendu) suffit pour l'état de quelques milliers d'instances lu par le vertex shader (≤ 4 096 vec4 par tableau, 64 Ko) ; deux tableaux (courant, précédent) donnent les vecteurs vitesse.
